# UDS Study Tool — 代码审查清单

## 审查概述

本文档定义了对 UDS Study Tool 项目进行代码审查的方法论和检查项。审查覆盖三个维度：

- **维度 A — 标准符合性检查（Cross-Reference Audit）**：对比代码中的服务、NRC、会话定义与 ISO 14229-1-2020 标准的符合性
- **维度 B — 代码质量与漏洞检查（Code Quality Audit）**：检查 JS 代码质量、逻辑缺陷、安全风险
- **维度 C — 完整性与遗漏检查（Completeness Audit）**：检查是否存在遗漏的功能或内容

审查范围包括 `uds_learning_tool.html`（学习工具）和 `uds_simulator.html`（模拟器）两个核心 HTML 文件。审查仅报告发现，不修改代码。

---

## 维度 A — 标准符合性检查

**目的**：对比代码中的服务/NRC/会话定义与 ISO 14229-1 标准的符合性。

### 审查基础资料

- 标准来源：`doc/md/【原文】ISO 14229-1-2020.md` 及 `doc/ISO 14229-1-2020.pdf`
- 关键标准表格：Table 2（服务标识符）、NRC 定义表、会话定义表
- 十六进制归一化规则：标准文档中 "1016" 格式统一视为 "0x10" 进行比较

---

### A1. 学习工具 SERVICES vs 标准

- **方法**：读取 ISO 14229-1 标准 Table 2，提取所有定义的 SID、名称、子功能。对比学习工具 `SERVICES` 数组（约第 408 行）中的 26 个服务定义。
- **对照要素**：SID 值（归一化后）、服务全名（name）、缩写（shortName）、功能单元（unit）、子功能列表（subfuncs）、消息格式（reqFmt/resFmt）
- **PASS**：所有 26 个服务的 SID、名称、子功能与标准完全一致
- **FAIL**：存在 SID 不匹配、名称错误、子功能遗漏或多余、消息格式描述错误
- **NA**：N/A

### A2. 模拟器 SID_INFO vs 标准

- **方法**：读取模拟器 `SID_INFO` 对象（约第 446 行），提取所有定义的服务。对比标准 Table 2。
- **对照要素**：SID、名称（name）、是否有子功能（hasSF）、子功能定义（sfs）
- **PASS**：所有实现服务的 SID、名称、子功能定义与标准一致
- **FAIL**：存在定义错误或与标准不符
- **NA**：模拟器未实现的服务不在检查范围内（仅检查已实现的）

### A3. 学习工具 NRCS vs 标准

- **方法**：对比学习工具 `NRCS` 数组（约第 674 行）中的 37 个 NRC 条目与标准 NRC 定义表。
- **范围展开规则**：标准或代码中使用范围表示的 NRC（如 '50-5D'）需展开为独立 NRC 列表再一对一对照。展开后统计独立 NRC 总数。
- **对照要素**：NRC 码值（val）、名称（name）、助记符（mne）、描述（desc）
- **PASS**：全部 NRC 的码值、名称、助记符、分类与标准一致
- **FAIL**：存在码值不匹配、名称翻译错误、助记符错误、分类错误
- **NA**：标准保留范围（ISO_SAE_Reserved）只需要名称和描述合理即可

### A4. 模拟器 NRC 常量 vs 标准

- **方法**：对比模拟器 `NRC` 常量对象（约第 534 行）中的 22 个 NRC 与标准 NRC 定义。
- **对照要素**：常量名（如 GR、SNS）、数值（如 0x10、0x11）
- **PASS**：所有 22 个 NRC 常量的名称-数值映射与标准一致
- **FAIL**：存在数值错误、常量名不符合标准术语
- **NA**：N/A

### A5. 学习工具 SESSIONS vs 标准

- **方法**：对比学习工具 `SESSIONS` 数组（约第 751 行）中的 4 个会话定义与标准会话定义。
- **对照要素**：会话码值（01-04）、会话名称、描述、支持的服务列表（services）、会话转换关系（transitions）
- **PASS**：每个会话的码值、名称、服务列表与标准分配一致
- **FAIL**：存在服务权限分配错误（缺少应支持的服务、多出不支持的服务）
- **NA**：N/A

### A6. 模拟器 SESSION_RULES vs 标准

- **方法**：对比模拟器 `SESSION_RULES` 权限矩阵（约第 550 行）与标准定义的会话-服务权限映射。检查每个服务的 4 个会话权限值（0=不支持、1=支持、2=需安全解锁）。
- **对照要素**：每个 SID 在 Default/Programming/Extended/SafetySystem 会话中的权限值
- **PASS**：权限分配与标准一致（含 SafetySystem 通过代码自动继承 Extended 的规则）
- **FAIL**：存在权限过高（安全敏感服务在不应支持的会话中被标记为支持）或权限过低（应在某会话支持的服务被遗漏）
- **NA**：模拟器未实现的服务不在检查范围内

### A7. DID 标识符合理性

- **方法**：检查模拟器 `dids` 对象（约第 405 行）中的 DID 赋值。DID 范围 F190-F19C 和 F300-F302 对应的数据是否有意义。
- **对照要素**：DID 命名是否符合标准建议范围、初始值是否合理（如 F19A 环境温度值）
- **PASS**：所有 DID 在合理范围内，初始值有意义，命名符合标准
- **FAIL**：存在不合理赋值（如 F19A 环境温度值明显错误——当前注释为 0x84 但应为 0x15）
- **NA**：N/A

## 维度 B — 代码质量与漏洞检查

**目的**：检查 JS 代码质量、逻辑缺陷、安全风险。

### B1. JS 语法与类型错误

- **方法**：逐行扫描两个 HTML 文件的 `<script>` 中 JS 代码，检查隐式全局变量、未定义引用、类型不一致、严格模式违规。
- **检查工具**：LSP diagnostics + 手动审查
- **PASS**：无语法错误、无类型错误、无隐式全局变量
- **FAIL**：存在任何 JS 语法错误、未定义变量引用、类型不一致
- **NA**：N/A

### B2. 逻辑缺陷

- **方法**：检查条件分支逻辑、空值/undefined 处理、运算符正确性（如 === 与 ==）、取反逻辑、比较方向。
- **重点区域**：
  - `handleDSC` 中 suppressResponse 处理逻辑
  - `checkSessionSecurity` 中 security bypass 判断
  - `transferData` 序列号验证逻辑（允许重传的处理）
  - 消息解码逻辑中的条件判断
- **PASS**：逻辑正确，条件分支无遗漏
- **FAIL**：存在逻辑错误（如条件判断反了、运算符误用、空值未处理）
- **NA**：N/A

### B3. 边界条件

- **方法**：检查空数组处理、非预期输入、索引越界访问、HEX 输入验证边界。
- **重点区域**：
  - `bytes.length` 最小长度检查
  - 空值输入处理（如未选择 SID、未输入数据字节）
  - 数组/对象 key 存在性检查
  - HEX 输入过滤（含非法字符、奇数长度、空格处理）
- **PASS**：边界处理正确，输入验证充分
- **FAIL**：存在未处理的边界情况（如空输入导致崩溃、越界访问）
- **NA**：N/A

### B4. 控制流完整性

- **方法**：检查 switch/case 语句是否有 default 分支、所有条件分支是否有 return/break、函数是否有明确的返回路径。
- **重点区域**：`processRequest` 引擎中的 24+ 个 `handle*` 函数
- **PASS**：所有 switch 有 default，所有分支正确处理，无遗漏
- **FAIL**：存在分支遗漏（如 default 缺失、某条件分支无处理）
- **NA**：N/A

### B5. XSS 与安全风险

- **方法**：检查 `innerHTML` 使用频率和场景、用户输入是否经过转义处理、动态 HTML 拼接是否涉及未过滤的用户输入。
- **重点区域**：学习工具和模拟器中的 HTML 模板拼接、搜索框输入处理、HEX 原始输入处理
- **PASS**：所有动态内容经过安全处理，XSS 风险可控
- **FAIL**：存在未过滤的用户输入被拼接到 HTML 中、存在明显 XSS 漏洞
- **NA**：N/A

### B6. 注释质量

- **方法**：检查误导性注释、TODO 标记、已知错误注释、注释与代码实际行为不一致。检查 `updateDynamicDIDs` 中 DID 值更新逻辑与注释的关系。
- **重点区域**：F19A 环境温度注释错误（约第 416 行）、TODO 标记、代码中自相矛盾的注释
- **PASS**：注释准确反映代码行为，无误导性注释
- **FAIL**：存在错误或误导性注释（如 F19A 注释用 0x84 但应为 0x15）
- **NA**：N/A

### B7. 已知 Bug 确认

- **方法**：确认已知问题是否仍存在。包括 F19A 值错误、FlexRay 重复文件、数据同步问题（两个 HTML 的服务数据独立维护导致的不一致）。
- **PASS**：已知问题已识别并记录，没有发现新的未记录问题
- **FAIL**：存在未记录的新问题，或已知问题的描述不符合实际情况
- **NA**：N/A

## 维度 C — 完整性与遗漏检查

**目的**：检查是否存在遗漏的功能或内容。

### C1. 标准有代码无的缺失服务

- **方法**：按功能单元分组，列出 ISO 14229-1 标准中定义了但代码中未实现的服务。标准共有约 60+ 个服务，代码中学习工具实现了 26 个，模拟器实现了约 24 个。缺少的服务按功能单元归类。
- **重要说明**：缺少的 34+ 个标准服务是范围决策，并非代码缺陷。此检查项仅做记录，不影响 PASS/FAIL 判定。
- **PASS**：缺少的服务已识别并确认是范围决策
- **FAIL**：存在非预期遗漏（即本应在范围内但未实现的服务）
- **NA**：N/A

### C2. NRC 数量差异

- **方法**：对比标准 NRC 总数、学习工具 37 个 NRC 条目、模拟器 22 个 NRC 常量。展开范围值（如 '01-0F'）后计算独立 NRC 总数。记录数量差异并分析原因。
- **PASS**：数量差异已记录，且有合理解释（如模拟器仅包含常用 NRC）
- **FAIL**：存在未记录的不一致，或差异无法解释
- **NA**：N/A

### C3. 学习工具 6 标签页功能完整性

- **方法**：验证学习工具的 6 个标签页（服务浏览器、SID 服务地图、NRC 参考、会话管理、消息构造器、知识测验）的功能是否完整。
- **检查项**：每个标签页的渲染函数是否定义（renderServices、renderHexMap、renderNRCs、renderSessions、initBuilder、startQuiz）、搜索筛选是否工作、模态弹窗是否正确显示
- **PASS**：全部 6 个标签页功能完整、正确工作
- **FAIL**：存在未实现的标签页功能或功能异常
- **NA**：N/A

### C4. 模拟器功能完整性

- **方法**：验证模拟器的三大面板（ECU 状态、消息日志、消息构造器）和 13 个预设场景的功能是否完整。
- **检查项**：所有面板 UI 正确渲染、13 个场景按钮触发正确流程、ECU 状态实时更新、消息日志正确显示请求/响应/负响应
- **PASS**：所有面板和 13 个场景正常工作
- **FAIL**：存在面板内容缺失或场景无法运行
- **NA**：N/A

### C5. 标准文档完整性

- **方法**：检查 `doc/md/` 和 `doc/` 目录下标准文档是否齐全。标准应包含 Part 1-7 共 7 个部分的文档。
- **检查项**：文件是否存在、命名是否规范、FlexRay 文件是否存在重复
- **PASS**：所有标准文档存在且命名规范
- **FAIL**：存在缺失文档或命名异常
- **NA**：N/A

### C6. PDF 文件完整性

- **方法**：检查 `doc/` 下所有 PDF 文件是否存在且可解析读取（至少能提取关键表 Table 2 的内容）。
- **检查项**：文件存在性、文件大小合理、可读取内容
- **PASS**：PDF 文件全部存在且可解析
- **FAIL**：缺少 PDF 文件或文件损坏不可解析
- **NA**：N/A

### C7. 额外验证 — 服务列表完整性

- **方法**：检查学习工具 `SESSIONS` 中每个会话的 `services` 列表是否包含预期服务。特别验证 Authentication（0x29）是否出现在服务列表中（2020 版新增服务）。
- **PASS**：服务列表完整，包括 0x29（Authentication）在内的所有预期服务均已包含
- **FAIL**：存在服务遗漏（如 0x29 未在 SESSION.services 中列出）
- **NA**：N/A

## 审查执行说明

### 执行规则

1. **逐项审查**：按 A1-A7、B1-B7、C1-C7 顺序逐项执行，每项给出 PASS/FAIL/NA 判定
2. **记录规范**：
   - PASS 项：简要说明通过理由
   - FAIL 项：记录文件位置（函数/对象名）、问题描述、预期 vs 实际、严重级别
   - NA 项：说明不适用的原因
3. **严重级别**（仅维度 B 使用）：
   - **BUG**：严重缺陷，可能导致功能异常或数据错误
   - **WARNING**：一般问题，可能引发异常但有防护机制
   - **INFO**：建议改进，不影响功能但可优化

### 输出文档格式

审查结果统一记录到 `docs/CODE-REVIEW-FINDINGS.md`（任务 4/5/6 产出），最终综合为结构化报告 `docs/CODE-REVIEW-REPORT.md`（任务 7 产出）。每个发现条目应包括：

```
### 问题编号
- **维度/子项**: A3 / B2
- **文件**: uds_simulator.html
- **位置**: function handleDSC, ~行号
- **发现**: [问题描述]
- **预期**: [标准/正确行为]
- **实际**: [当前代码行为]
- **严重级别**: BUG / WARNING / INFO
- **判定**: FAIL
```
