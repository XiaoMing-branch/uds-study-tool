# UDS Study Tool — ISO 14229-1 统一诊断服务学习工具

## 项目简介

UDS（Unified Diagnostic Services，统一诊断服务）是 ISO 14229-1 标准定义的汽车电子诊断协议，广泛应用于车载 ECU 的故障诊断、软件刷写、标定和测试。对于刚接触嵌入式汽车电子开发的工程师来说，UDS 协议内容繁杂，包含 26 种服务、37 个负响应码、多种诊断会话和安全访问机制，学习曲线较陡。

本项目包含两个纯前端的 HTML 页面，无需安装、无需后端、无需网络，在浏览器中打开即可使用：

- **uds_learning_tool.html** — 知识学习工具，涵盖 UDS 协议的全部核心知识点
- **uds_simulator.html** — 交互式 ECU 模拟器，可在浏览器中模拟真实诊断通信

两个页面配合使用，让你在阅读标准的同时动手实践，快速掌握 UDS 诊断协议。

## uds_learning_tool.html 功能介绍

学习工具将 ISO 14229-1 的知识点整理为 6 个标签页，方便按需查阅。

### 服务浏览器

展示全部 26 个 UDS 服务的完整列表。每个服务以卡片形式呈现，包含：

- SID（Service Identifier，服务标识符），如 0x22、0x3E
- 服务名称和简称，如 ReadDataByIdentifier (RDBI)
- 所属功能单元（诊断与通信管理、数据传输、存储数据传输、IO 控制、例行程序、上传下载、安全子层）
- 中文描述
- 关联的 NRC 列表

**搜索与筛选**：可按服务名称、SID 值或描述关键词搜索，也可按功能单元分类筛选。页面顶部的统计卡片会实时更新匹配数量。

**详情弹窗**：点击任意服务卡片打开详情弹窗，包含完整描述、子功能参数表、消息请求/响应格式、会话可用性（哪些会话支持该服务）、以及每个关联 NRC 的解释。

### 服务地图

以 0x00 到 0xFF 共 256 个格子的十六进制网格展示 SID 地址空间。四种颜色标识：

- 蓝色 — 定义的 UDS 服务
- 红色 — 负响应码（NRC）
- 绿色 — 诊断会话类型
- 灰色 — 保留/其他

鼠标悬停显示简要名称，点击服务格子直接跳转到详情弹窗。支持按 SID 值搜索高亮。

### NRC 参考

展示全部 37 个负响应码（含 0x78 RCRRP 等特殊码），每个 NRC 包含：

- 十六进制码值（如 0x13、0x22、0x33）
- 标准名称（如 incorrectMessageLengthOrInvalidFormat）
- 助记符（如 IMLOIF）
- 中文详细说明
- 分类标签（通信相关 / 条件错误 / 保留）

支持按码值、名称、描述搜索，以及按分类筛选。范围值（如 01-0F）也能正确匹配区间搜索。

### 会话管理

展示 4 种诊断会话的完整信息：

- **Default Session (0x01)** — 默认会话，ECU 上电后自动进入
- **Programming Session (0x02)** — 编程会话，用于 ECU 刷写
- **Extended Diagnostic Session (0x03)** — 扩展诊断会话，用于高级功能
- **Safety System Diagnostic Session (0x04)** — 安全系统诊断会话（2020 版新增）

页面为每个会话列出支持的服务列表，并用颜色标签区分服务独占性（通用服务、编程专属、扩展专属、安全系统专属）。底部有会话转换关系图，展示 DiagnosticSessionControl (0x10) 如何在会话间切换。

### 消息构造器

交互式构建 UDS 诊断消息的工具。操作步骤：

1. 从下拉菜单选择服务（SID）
2. 如果该服务有子功能参数，自动展开子功能选择
3. 输入 HEX 格式的数据字节
4. 实时预览请求消息和预期的正响应/负响应格式

请求消息用颜色标识每个字节的作用（蓝色 = SID，黄色 = 子功能，绿色 = 数据）。同时显示正响应（SID+0x40）和负响应（0x7F + SID + NRC）的格式。

### 主题切换

右下角按钮可在深色/浅色主题间切换，选择会保存到浏览器本地存储。

## uds_simulator.html 功能介绍

模拟器模拟了一个完整的 ECU，包含状态机、服务处理器、DID 存储和计时器。页面采用深色主题的专业诊断工具风格，分为三个面板。

### ECU 状态面板（左侧）

实时显示模拟 ECU 的当前状态：

- **当前会话** — Default / Programming / Extended / SafetySystem
- **安全等级** — Locked（锁定）或 Unlocked（已解锁）
- **P2 / P2\* / S3 计时器** — 响应超时与会话超时参数
- **通信模式** — Normal / Off
- **计数器** — 已收消息数、已发消息数、正响应数、负响应数
- **DID 值列表** — 16 个模拟 DID 的当前值，含 VIN 码（F190）、硬件版本号（F191）、软件版本号（F192）、ECU 名称（F193）、水温（F194）、转速（F195）、车速（F196）、里程（F197）、供电电压（F199）、环境温度（F19A）、油量（F19C）等

会话切换和 ECU 复位时安全等级自动重置为锁定状态，符合真实 ECU 行为。

### 消息日志（中间面板）

实时显示所有诊断消息的通信记录。每条消息包含：

- 时间戳（时:分:秒.毫秒）
- 方向指示（▶ 请求 / ◀ 正响应 / ✕ 负响应）
- HEX 字节内容
- 解码后的中文描述

请求消息左侧有蓝色标记，正响应为绿色，负响应为红色，一目了然。支持一键清空日志。

### 消息构造器（右侧面板）

完整的诊断消息构造工具：

- **SID 选择器** — 下拉菜单列出所有支持的服务（24+ 个服务处理器）
- **子功能选择** — 当所选服务有子功能时自动展开
- **数据字节输入** — HEX 格式，空格分隔
- **DID 快捷按钮** — 选择 ReadDataByIdentifier 或 WriteDataByIdentifier 时自动显示 11 个常用 DID 按钮，一键填入
- **请求预览** — 实时显示构建中的请求消息，颜色标记字节类型
- **预期响应预览** — 显示正响应和负响应的预期格式
- **解码信息** — 自动解析消息内容，显示服务名称、子功能、DID 标识和物理值换算（如水温、转速、车速）
- **发送按钮** — 发送消息到模拟 ECU
- **原始 HEX 发送** — 直接输入 HEX 字节发送，自动识别 SID 并更新构造器

发送后 ECU 会模拟 P2 响应延时（默认 50ms），再返回响应消息。

### 13 个预设场景

一键运行完整诊断流程，适合初学者快速体验：

| 场景 | 说明 |
|------|------|
| 进入默认会话 | 发送 10 01，切换到默认会话 |
| 进入扩展会话 | 发送 10 03，切换到扩展会话 |
| 进入编程会话 | 发送 10 02，切换到编程会话 |
| TesterPresent | 发送 3E 00，保持会话活跃 |
| 读取 VIN（DID F190） | 发送 22 F1 90，读取 VIN 码 |
| 读取 DTC 状态 | 发送 19 02，按状态报告 DTC |
| SecurityAccess 解锁 | 完整种子-密钥流程：进入扩展会话 → 请求种子 → 发送密钥 |
| ECU 硬复位 | 发送 11 01，ECU 复位到默认会话 |
| 完整诊断流程演示 | 7 步流程：扩展会话 → 安全解锁 → 读 VIN → 读 DTC → 清 DTC → TP 保活 |
| 清除 DTC | 发送 14 FF FF FF，清除所有故障码 |
| 批量读取 DID | 一次请求读取 F190、F192、F193 三个 DID |
| 启动校验例程 | 发送 31 01 FF 02，启动 checksum 例行程序 |
| 下载流程演示 | 7 步流程：进入编程会话 → RequestDownload → 4 次 TransferData → RequestTransferExit |

## CAN 总线与 LIN 总线通信

ud2 工具现已集成 CAN 总线 (ISO 11898) 和 LIN 总线 (ISO 17987) 通信模式的教学与模拟。

### uds_learning_tool.html — 新增标签页

学习工具新增 2 个知识标签页：

- **🚌 CAN 总线** — CAN 2.0A/B 帧结构、CSMA/CR 仲裁原理、5 种错误检测、TEC/REC 错误状态机、CAN FD 对比
- **📡 LIN 总线** — LIN 帧结构 (同步间隔/0x55/PID/数据/校验和)、主从架构、调度表、CAN vs LIN 对比表

CAN/LIN 总线内容已整合到独立的标签页中，可在"CAN 总线"和"LIN 总线"标签页查看详细的技术说明。

### uds_simulator.html — CAN 面板增强

现有 CAN 面板深度增强：

- **帧格式切换** — 支持 CAN 2.0A (标准 11-bit ID)、CAN 2.0B (扩展 29-bit ID)、CAN FD 三种格式
- **错误注入** — 5 种错误类型: CRC 错误、ACK 错误、填充错误、格式错误、总线关闭 (Bus Off)
- **总线状态机** — TEC/REC 计数器实时跟踪，自动在 Error Active → Error Passive → Bus Off 之间转换
- **仲裁演示** — 可视化多节点竞争过程，展示低 ID 优先的 CSMA/CR 机制
- **帧结构标注** — Toggle 开关显示每个 CAN 帧字段的颜色标注 (SOF/仲裁/控制/数据/CRC/ACK/EOF)
- **总线负载率** — 实时计算并显示近 1 秒内的总线占用百分比

### uds_simulator.html — LIN 面板新增

新增完整的 LIN 总线模拟面板：

- **主从模式** — Master 与 Slave 双角色，主节点维护调度表
- **调度表** — 预设 5 个典型 LIN 信号 (车速/转速/水温/灯光/主节点状态)
- **帧日志** — 实时显示 LIN 帧的同步字节、PID (含奇偶校验)、数据、校验和
- **唤醒/休眠** — 模拟 LIN 总线的唤醒脉冲 (250μs) 和休眠命令
- **校验和** — 使用 LIN 2.0 增强校验和算法计算

### 新增预设场景

| 场景 | 说明 |
|------|------|
| CAN 仲裁演示 | 演示 3 个节点 (0x7E0/0x7E8/0x7F0) 竞争总线, 低 ID 获胜 |
| CAN 错误注入 | 连续触发填充错误 + CRC 错误, 观察 TEC/REC 变化 |
| CAN Bus Off | 强制 TEC > 255, 节点进入 Bus Off 状态 |
| LIN 调度演示 | Master 按 600ms 间隔发送车速/转速/水温/灯光/状态帧 |
| LIN 唤醒 | 发送 250μs 显性唤醒脉冲 |

### 自动 TesterPresent

开启后，ECU 在非默认会话中每 2 秒自动发送一条 3E 00 消息，模拟真实诊断工具的行为，防止会话超时。

### ECU 复位

一键将 ECU 恢复到默认状态（Default 会话、锁定安全、计数器清零）。

## 快速开始

以下是一个面向新手的上手路径，建议按顺序操作。

### 第 1 步：打开学习工具

直接用浏览器打开 `uds_learning_tool.html`。你会看到左侧导航栏列出 6 个标签页。

先浏览 **服务浏览器** 标签页。滚动查看 26 个 UDS 服务，点击任意卡片查看详情。试试在搜索框输入"读取"或"0x22"，观察列表如何过滤。

### 第 2 步：了解会话和 NRC

切换到 **会话管理** 标签页。了解 4 种会话的区别：Default 是基础会话，Programming 用于刷写，Extended 用于高级诊断。注意哪些服务只能在特定会话中使用。

切换到 **NRC 参考** 标签页。熟悉常见的负响应码：0x11（服务不支持）、0x22（条件不正确）、0x33（安全访问被拒绝）。这些会在模拟器中频繁遇到。

### 第 3 步：打开模拟器

用浏览器打开 `uds_simulator.html`。你会看到深色主题的三栏布局。左侧显示 ECU 状态（当前为 Default 会话、Locked 状态），中间是消息日志，右侧是消息构造器。

### 第 4 步：运行场景

在左侧 **场景快速执行** 区域，点击 **进入扩展会话**。观察消息日志中出现：

```
▶ 10 03 — DiagnosticSessionControl 请求
◀ 50 03 ... — 正响应，会话切换为 Extended
```

左侧 ECU 状态面板的"会话"变为 Extended，"安全等级"仍为 Locked。

接着点击 **SecurityAccess（种子→密钥）** 场景。观察完整的解锁流程：

1. 请求种子（27 01）→ ECU 返回种子值
2. 发送密钥（27 02 12 34 56 78）→ ECU 验证成功，状态变为 Unlocked

### 第 5 步：手动发送消息

在右侧消息构造器中：

1. 选择服务 ReadDataByIdentifier (0x22)
2. DID 快捷按钮区域出现，点击 **F190 VIN**
3. 数据字节自动填入 F1 90
4. 预览区显示请求消息：`22 F1 90`
5. 点击 **发送请求**
6. 日志中出现响应消息：`◀ 62 F1 90 ...`，包含 VIN 码数据

### 第 6 步：尝试完整流程

点击 **完整诊断流程演示** 场景，一次性观察 7 步诊断流程。这是真实汽车诊断中最常见的操作序列，帮助你建立完整的通信流程概念。

## 提示与建议

- 学习时两个页面配合使用：在学习工具中查阅服务详情，再到模拟器中动手发送该服务
- 尝试在模拟器中发送学习工具里看到的 NRC 场景，比如在不安全的状态下尝试写 DID（0x2E），观察 ECU 返回 0x33（securityAccessDenied）
- 模拟器支持 WriteDataByIdentifier（0x2E），可以尝试修改 DID 的值
- 使用原始 HEX 发送功能可以发送任意字节序列，用于测试边界情况
- 所有功能都在浏览器本地运行，你的操作记录不会上传到任何服务器
